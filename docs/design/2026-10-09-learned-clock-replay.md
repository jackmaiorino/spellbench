# Clock-sensitive learned replay

The published Exp1 profile retains its original 96 visits or 12-second search stopping rule. Fresh same-seed policy runs can therefore return different selections. Generation154 completed two natural games but its strict policy-repeat primary hashes differed; that failed receipt remains unchanged. Its only differing selections swapped the order of two Kiora discards, with differing neural-call counts. This is not a successful policy repeat or a completed rating.

The existing protocol distinguishes this from engine replay: clock-reading bots are conforming, fresh game identity is conditional on wall-time independence, and the same engine, rules, decks, seed and selections must reproduce the game digest. The separate `xmage_neural_game_check.py` recorded mode binds an existing public-traffic file and primary store by SHA256. It runs the actual engine with the saved model selections and the same heuristic, checking every complete public payload while excluding only the choose payload's volatile `clock.remaining_ms`. Observations, offered candidates, game ids, rules and maximum clocks remain exact. It requires the complete original primary store, including game digest, to match byte for byte. It also captures all engine exchanges and uses the existing conformance replay to compare every complete engine response. It makes zero new model requests and reports `engine_replay_identical` independently from `policy_repeat_identical`; default strict policy-repeat mode is preserved.

`xmage_native_benchmark_qualify.py --clock-sensitive` is an explicit opt-in to the existing generic throughput guard's variability disposition. The guard repeats the complete serial sample if worker counts change outputs and refuses any cross-worker change that the serial repeat reproduces. The native wrapper retains its strict default and additionally requires the matching natural trial ledgers plus a full retained serial repeat in the same measurement directory. Its receipt binds that serial ledger's hash and every changed index. It never labels these policy outputs identical. This compatibility work changes no checkpoint, model runtime identity, search setting, image, deck, clock or scheduled rated game. Actual guarded replay and completed-work qualification remain required; source tests are not gameplay evidence.
