# Clock-sensitive learned replay

The published Exp1 profile retains its original 96 visits or 12-second search stopping rule. Fresh same-seed policy runs can therefore return different selections. Generation154 completed two natural games but its strict policy-repeat primary hashes differed; that failed receipt remains unchanged. Its only differing selections swapped the order of two Kiora discards, with differing neural-call counts. This is not a successful policy repeat or a completed rating.

The existing protocol distinguishes this from engine replay: clock-reading bots are conforming, fresh game identity is conditional on wall-time independence, and the same engine, rules, decks, seed and selections must reproduce the game digest. The separate `xmage_neural_game_check.py` recorded mode binds an existing public-traffic file and primary store by SHA256. It runs the actual engine with the saved model selections and the same heuristic, checking every complete public payload while excluding only the choose payload's volatile `clock.remaining_ms`. Observations, offered candidates, game ids, rules and maximum clocks remain exact. It requires the complete original primary store, including game digest, to match byte for byte. It also captures all engine exchanges and uses the existing conformance replay to compare every complete engine response. It makes zero new model requests and reports `engine_replay_identical` independently from `policy_repeat_identical`; default strict policy-repeat mode is preserved.

`xmage_native_benchmark_qualify.py --clock-sensitive` is an explicit opt-in to the existing generic throughput guard's variability disposition. The guard repeats the complete serial sample if worker counts change outputs and refuses any cross-worker change that the serial repeat reproduces. The native wrapper retains its strict default and additionally requires the matching natural trial ledgers plus a full retained serial repeat in the same measurement directory. Its receipt binds that serial ledger's hash and every changed index. It never labels these policy outputs identical. This compatibility work changes no checkpoint, model runtime identity, search setting, image, deck, clock or scheduled rated game. Actual guarded replay and completed-work qualification remain required; source tests are not gameplay evidence.

Generation155 observed the separate proof: complete original primary SHA256 `705c38fcd98abbb685bc664f9afd12c3d75e477f69e48ef972a77b720aefde42` reproduced, 322 complete engine exchanges replayed identically, zero model requests, 31.332 seconds, authenticated reservation released. The operator-only complete result is sealed on E: with verified D: recovery, index `6ab478044f1ef0dd03d94d83e369d884de09a41473f4a3cb2775c7e7b041975e`. This does not relabel154's policy repeat.

Production recording is optional and disabled by default. `SPELLBENCH_ENGINE_RECORDING` and its SHA256 pin select a bounded configuration containing source hashes, the exact SSH collector settings, hot record root, cold E: and recovery D: destinations, copy deadlines, per-game byte ceiling and destination storage caps/reserves. Qualification and formal playback use the same explicit settings; their workload identity binds the five capture/runner/executor/qualification/collector source files and all transport settings. Transcript writes fail before crossing the byte ceiling. A READY receipt appears atomically after full transcript/terminal-row fsync and verified private database/container cleanup. The ordered parent callback serializes its ledger, checks that exact row against READY, and waits under the job's independent reservation, STOP and storage supervision for two-copy custody acknowledgment. The worker window replenishes only after that callback succeeds. Failed collection retains the trace and stops replenishment; interrupted or dropped in-flight games remain operator attempts, outside the committed result prefix.

The collector admits raw D: staging before SCP, then verifies and fsyncs complete terminal row, READY and losslessly compressed exchanges on both destinations, verifies decompression, and atomically publishes its exact digest receipt. Only then may the callback release its redundant hot transcript; row and custody receipts remain. Actual generation155 trace compressed from3,778,300 to85,766 bytes with exact reconstruction. Both transfer and compression run inside measured completed-work time. Raw captures include the game secret and private engine state and remain operator-only outside leaderboard artifacts. The supported launch path is the owned qualified-job controller followed by pinned benchmark tools; this does not claim every raw frontend is universally guarded.
