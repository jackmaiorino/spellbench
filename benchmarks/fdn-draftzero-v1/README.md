# DraftZero Exp1 FDN mirrors

The full round robin contains public gen0, gen10 and gen33 checkpoints, DraftZero's FDN graph network, and uniform and heuristic anchors: 1,920 games, sixteen public FDN decks, four seat-swapped pairs per deck and matchup. Each matchup has 64 complete pairs; each entrant has 640 scheduled games. Ratings are comparable only within this benchmark's engine, decks and clock. Deck attribution and lists follow `fdn-mirror-v0` and the XMage FDN catalog.

All checkpoints use the published final-evaluation `published-exp1-final-eval-fair-v1` settings, including 96 visits and the source's 12-second clock after a legal future. These are named fair variants: permitted hidden-world reconstruction, own-visible replay and disabled opponent-hand encoding change the source evaluation. Confined CPU float32 inference differs from the released float16 run. The adapter owns checkpoint loading inside its pinned Docker image; checkpoint pickles are never loaded in the host process. Gen0 remains explicitly present as the released initialization checkpoint; it is not evidence of learning.

The definition pins each checkpoint through `checkpoint`, the mounted inference model source, feature vocabulary and action vocabulary, every engine jar, all 309 model classes, two model resources, the Commons Math dependency and adapter inputs through `evaluation_inputs`, plus the reviewed engine/model manifests, Java executable and confined image. Runtime versions bind the checkpoint, build and profile hashes. `engines/xmage/releases.json` supplies the exact upstream source and asset hashes. No weights or compiled binaries are checked into this directory.

`draftzero-fdn-gnn-100-fair` is DraftZero's FDN graph network (`danbrooks/draftzero-fdn-gnn@a8351e8b`, weights CC BY 4.0) with its released PIMC tree search at 100 simulations a decision. It is also a fair variant: one permitted sampled world with the opponent's hand hidden, confined CPU float32 inference, and the kit's declining answer where a world cannot be searched or a callback replayed. It runs on its own model build (the graph stage beside MageZero v0.2) next to this board's engine overlay; its pinned image is built from `integrations/xmage-models` with `--target gnn`. Docker image ids are not reproducible, so the run host loads that exact image (`docker save`/`docker load` keeps its id). Its placeholders are `XMAGE_GNN_RUNTIME` (`python/tools/xmage_gnn_runtime.py`), `XMAGE_GNN_SOURCE` (that tools directory), `XMAGE_GNN_MODEL_BUILD`, `XMAGE_GNN_MANIFEST` (the `engines/xmage/releases.json` it was built with) and `XMAGE_GNN_ROOT` (the release inputs).
